# Object Storage (S3-Compatible) :

## Overview

This session introduces the fundamentals of S3‑compatible object storage systems. While the term "S3" originates from Amazon, many vendors and open‑source projects implement the same API and concepts. The goal is to understand how object stores differ from traditional file systems and what design trade‑offs they make.

**Keep the discussion high level; focus on architecture, key operations, and common patterns rather than vendor specifics.**

3. **Durability, Distribution & Scaling Architecture:** How do object stores achieve durability at scale using replication or erasure coding? Explain how data and metadata are distributed across nodes, how failures are detected and repaired, and how systems scale to billions of objects through partitioning and request routing.

s3 מנהל רפליקציות בכמה רמות. על דיסקים שונים, שרתים שונים וavailability zones שהם בעצם חוות שרתים שונות.
לכל חוות שרתים כזאת יש חשמל קירור ורשתות תקשורת שונות, וכך אפילו נפילה של חוות שרתים שלימה לא תפגע במידע.

s3 מבצע גם erausre coding על מנת לטפל במקרים של מידע שאבד. בעצם מג'נרטים M parity chunks. כל הבלוקים מקודדים בתוכם את המידע כך שכל M צ'אנקים שילכו לאיבוד בדרך, נוכל לבנות מחדש באמצעות מה שנותר.
למשל עבור קובץ בגודל 10MB, 4 chunks כל אחד בגודל 2.5MB ו2 parity chunks, נוכל לבנות את המידע מחדש ללא תלות באיזה chunks נקבל, כל עוד נקבל 4.

לכל אובייקט יש מטא דאטא שנשמר בנוסף למידע עצמו. המטא דאטא נשמר בבאקטים מסוג table buckets שיותר מובנים למידע טבלאי. באופן כללי המטא דאטא נשמר בנפרד למידע עצמו.
s3 מנטר על הדיסקים בפועל ויודע לטרגר מעבר של מידע במידה ודיסקים נכשלים. כל דיסק לא מגיע לניצולת מלאה בשביל שבמידה ויש בעיה הם יוכלו לאחסן מידע מדיסקים תקולים.

ניתן להשתמש בpartitioning כדי לתשאל מידע יותר ביעילות.
על ידי חלוקה לpartitions (על ידי הkey) במבנה דמוי תיקיות, ניתן לתשאל רק partition ספציפי.

4. **Consistency & Performance:** What consistency guarantees do modern object stores provide (eventual vs strong)? How do multipart uploads, parallelism, and range reads affect performance? Discuss trade-offs for small vs large objects and listing operations.

strong - פעולת קריאה תמיד תחזיר את מה שקרא אחרי הכתיבה העדכנית ביותר שהתקבלה

eventual - הרפליקות מתכנסות לאורך זמן אבל קריאה יכולה להיות לא עדכנית.

מערכות object-storage מודרניות מספקות strong consistency

ניתן להשתמש בmultipart uploads כלומר העלאה של הקובץ בחלקים על מנת למזער סיכון לבעיות רשת, לשלוח כמה parts במקביל והפסקה של העלאה באמצע והמשך שלה מאוחר יותר.
באמצעות range read, ניתן לקרוא קובץ כלומר רק range של בתים, ועל ידי זה לאפשר קריאה מקבילית וכושר התאוששות מאיבוד של חלק.

אם מתעלמים ממחיר של פעולות api יש עוד חסרון לקבצים קטנים, יש overhead של קריאת metadata על כל קובץ קטן בנוסף לקפיצות לא אופטימליות בדיסק.
